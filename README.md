# telegram-llm-bot

Маленький Telegram-бот для закрытого чата друзей. Читает беседу, при желании
вставляет реплики «по делу», отвечает на упоминания и реплаи. Характер бота
задаётся одним текстовым файлом `persona.txt` — никакого программирования.

- **Стек:** Python 3.12 + [aiogram 3](https://docs.aiogram.dev/) + OpenAI-совместимый API.
- **Запуск:** `docker compose up -d` на любом сервере с Docker.
- **Совместимость:** работает с любым OpenAI-совместимым провайдером —
  оригинальным OpenAI, российскими прокси (proxyapi.ru, vsegpt.ru, neuroapi.host),
  OpenRouter, локальными моделями через Ollama и т.п.

---

## Что умеет

- Отвечает на прямые упоминания (`@my_bot ...`) и на реплаи на свои сообщения.
- В групповом чате читает все сообщения и САМ решает, когда вмешаться. Между
  «инициативными» репликами выдерживает кулдаун (по умолчанию 60 секунд),
  чтобы не спамить.
- Помнит последние N сообщений (по умолчанию 20) как контекст.
- Работает только в чатах из белого списка `ALLOWED_CHAT_IDS`.
- Управляющие команды доступны только указанным в `ADMIN_USER_IDS` админам.
- Чтобы поменять «характер» — просто отредактируйте `persona.txt` и
  выполните `docker compose restart bot`. Перекомпилировать ничего не нужно.

### Команды

Публичные (работают у всех в разрешённых чатах):

| Команда   | Что делает                                              |
| --------- | ------------------------------------------------------- |
| `/chatid` | Показать `chat_id` текущего чата (для `ALLOWED_CHAT_IDS`) |
| `/whoami` | Показать ваш `user_id` (для `ADMIN_USER_IDS`)             |

Только для админов (`ADMIN_USER_IDS`):

| Команда    | Что делает                                              |
| ---------- | ------------------------------------------------------- |
| `/persona` | Показать текущий системный промпт                        |
| `/reload`  | Принудительно перечитать `persona.txt`                   |
| `/mute`    | Заглушить бота в этом чате (он перестаёт отвечать)       |
| `/unmute`  | Снять заглушку                                           |
| `/status`  | Показать состояние: модель, кулдаун, история, заглушка   |

> Если `ADMIN_USER_IDS` не задан, управляющие команды не работают НИ ДЛЯ КОГО.
> Это сделано специально: лучше потребовать явной настройки, чем случайно
> отдать управление каждому участнику чата.

## Шаг 1. Создать самого бота в Telegram

1. В Telegram откройте чат с **@BotFather** и нажмите **Start**.
2. Команда `/newbot` → имя (как будет видно в чатах) → username
   (должен заканчиваться на `bot`, например `moy_chatik_bot`).
3. BotFather пришлёт **токен** вида `123456789:AAEa...`. Сохраните — это `BOT_TOKEN`.
4. **Очень важно:** команда `/setprivacy` → выберите своего бота → **Disable**.
   Без этого бот будет видеть только команды (`/что-то`), а не обычные сообщения,
   и читать чат у него не получится.
5. Добавьте бота в нужный закрытый чат как обычного участника.

## Шаг 2. Получить ключ к LLM

В России OpenAI напрямую заблокирован (нужен зарубежный IP и зарубежная карта).
Поэтому есть два сценария — выберите тот, что проще для вас.

### Вариант A. Российский OpenAI-совместимый прокси (рекомендуется)

Сервисы, которые принимают рубли (карта Мир / СБП), не требуют VPN и сами
ходят в OpenAI за вас:

- **proxyapi.ru** — самый известный, документация на русском.
- **vsegpt.ru** — много моделей, включая Claude и Gemini, через один ключ.
- **neuroapi.host** — аналогичный сервис.

Шаги: регистрируетесь → пополняете баланс на 200–500 ₽ → получаете API-ключ.
В `.env` пропишете:

```env
OPENAI_API_KEY=<ключ_от_сервиса>
OPENAI_BASE_URL=<base_url_сервиса>
```

Актуальные `base_url` смотрите в документации выбранного сервиса. На момент
написания: `https://api.proxyapi.ru/openai/v1`, `https://api.vsegpt.ru/v1`.

> На 10 человек траты копеечные: один ответ `gpt-4o-mini` стоит 0.10–0.30 ₽,
> то есть 500 ₽ хватит на тысячи реплик.

### Вариант B. Оригинальный OpenAI

Нужны зарубежная платёжная карта и сервер вне РФ (или прокси).

1. Заведите ключ на <https://platform.openai.com/api-keys>.
2. В `.env`: `OPENAI_API_KEY=sk-...`, `OPENAI_BASE_URL=` (пусто).
3. Если сервер всё-таки в РФ — пропишите в `.env` прокси:
   `HTTPS_PROXY=http://user:pass@host:port`.

## Шаг 3. Поставить Docker на сервер

Бот живёт в Docker — это значит, что один и тот же набор файлов запустится
одинаково на любом Linux-сервере (Ubuntu, Debian, Rocky и т.д.).

На свежем Ubuntu/Debian-сервере:

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
# Перелогиньтесь (закройте и откройте SSH-сессию заново),
# чтобы группа docker применилась.
```

Проверка: `docker version` должна показать версию без `sudo`.

> **Где хостить?** Минимальный VPS за 150–300 ₽/мес (Timeweb Cloud, Aeza,
> RuVDS — любой с Linux и SSH). 1 vCPU + 1 GB RAM хватит с большим запасом.
> Если используете прокси-провайдера из Варианта A, можно брать сервер
> в РФ — никаких проблем не будет.

## Шаг 4. Развернуть бота

```bash
# 1. Склонировать репозиторий
git clone <URL_вашего_репозитория> telegram-llm-bot
cd telegram-llm-bot

# 2. Создать .env из шаблона и отредактировать
cp .env.example .env
nano .env   # или любой редактор; впишите BOT_TOKEN, OPENAI_API_KEY и т.д.

# 3. (Опционально) Отредактировать персону
nano persona.txt

# 4. Собрать и запустить
docker compose up -d --build

# 5. Посмотреть логи
docker compose logs -f bot
```

После запуска зайдите в Ваш закрытый чат и отправьте две команды:

- `/chatid` — бот ответит числом (отрицательным для групп, например
  `-1001234567890`). Это значение для `ALLOWED_CHAT_IDS`.
- `/whoami` — бот ответит вашим `user_id` (положительное число). Это значение
  для `ADMIN_USER_IDS` — оно нужно, чтобы только Вы могли управлять ботом
  командами `/persona`, `/reload`, `/mute`, `/unmute`, `/status`.

Впишите оба значения в `.env`:

```env
ALLOWED_CHAT_IDS=-1001234567890
ADMIN_USER_IDS=123456789
```

Если хотите, чтобы помимо Вас управлять мог ещё кто-то — перечислите все
`user_id` через запятую: `ADMIN_USER_IDS=123456789,987654321`. Чужие
`user_id` Вы можете получить, попросив этих людей написать `/whoami` в чате.

Перезапустите бота, чтобы изменения вступили в силу:

```bash
docker compose restart bot
```

Теперь бот отвечает только в этом чате, и только Вы (как админ) можете им
управлять.

> Если сообщений в логах нет даже когда вы пишете в чат — почти наверняка
> забыли отключить privacy-режим у `@BotFather` (см. Шаг 1, пункт 4) или
> бот не добавлен в чат.

## Шаг 5. Менять характер бота

Откройте `persona.txt`, перепишите как хочется (можно по-русски, на любую
тему, любой длины — это просто текст), сохраните, выполните:

```bash
docker compose restart bot
```

Бот перечитает файл и будет отвечать в новой роли. Никакой пересборки
образа, никакой правки кода.

Примеры персон лежат в `examples/personas/`. Можете скопировать любую в
`persona.txt`:

```bash
cp examples/personas/butler.txt persona.txt
docker compose restart bot
```

## Частые вопросы

**Q: Бот не отвечает вообще.**
A: 90% случаев — privacy-режим у BotFather не отключён. Идите в @BotFather →
`/setprivacy` → ваш бот → Disable, затем удалите бота из чата и добавьте заново.

**Q: Бот отвечает на свои собственные сообщения / зацикливается.**
A: Не должен — он распознаёт себя по `from_user.id`. Если вдруг такое видите —
проверьте, что в чате не сидит ВТОРАЯ копия бота с тем же токеном.

**Q: Бот лезет в разговор слишком часто / слишком редко.**
A: Подкрутите `COOLDOWN_SECONDS` в `.env` (увеличьте до 120–180, чтобы был
сдержаннее) или поправьте persona.txt — добавьте инструкцию «вмешиваться
только если прямо спрашивают».

**Q: Хочу другую модель.**
A: В `.env` смените `MODEL=gpt-4o-mini` на любую доступную у вашего провайдера
(`gpt-4o`, `gpt-4-turbo` у OpenAI; у российских прокси список моделей в их
документации).

**Q: Бот отвечает в чужих чатах.**
A: Заполните `ALLOWED_CHAT_IDS` в `.env`. Без него бот отвечает везде.

**Q: Можно ли запустить на домашнем компьютере?**
A: Да, если он включён 24/7. Установите Docker Desktop и выполните те же
команды. Но любой VPS надёжнее.
